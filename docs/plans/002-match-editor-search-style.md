# 検索ヒットの配色を編集モードに揃える計画

## 状態

計算済みスタイルの動的取得を実装済み。Inkdrop のデバッグモードでの実機確認、ブラウザーでの回帰確認、整形確認が完了。

## 目的

プレビューの検索ヒットを、編集モードの `.cm-searchMatch` と同じテーマ配色で表示する。

## 修正案

1. 編集モードの DOM とスタイルの適用範囲を確認し、`.cm-searchMatch` と `.cm-searchMatch.cm-searchMatch-selected` の計算済みスタイルを `getComputedStyle()` で取得する方法を決める。実際の一致がない場合は、編集エリアと同じスタイル適用条件を持つ非表示の計測用要素を利用する。
2. 固定のテーマ変数への依存を置き換え、取得した背景色・文字色など、`::highlight()` が対応するプロパティを検索結果に反映する。ユーザー CSS の上書きも取得対象にする。
3. 検索時・次と前の移動時に取得内容を更新する。テーマやユーザー CSS の変更への追従方法、編集エリアが存在しない場合の取得方法も調査して実装する。取得できない状態では、取得済みの値があれば保持し、未取得の値を固定のテーマ配色で代用しない。
4. 計測用要素や動的なスタイルはプレビュー本文の外で管理し、不要になった時点で除去する。プラグイン無効化時にも後始末する。
5. CSS Custom Highlight API による描画を維持する。角丸・輪郭線など、同 API で再現できないプロパティは対象外とする。

プレビュー本文の DOM を変更せず、ユーザー CSS を含む `.cm-searchMatch` の計算済みスタイルから、対応する描画プロパティが検索ヒットへ反映されること。

## 初回実装結果（動的取得への修正前）

- インストール済み Inkdrop の `app.asar` 内のエディタ実装と `@inkdropapp/css/syntax.css` でテーマ変数を確認した。
- 通常の一致の背景色を `--editor-search-match-background-color`、選択中の一致の背景色を `--editor-search-match-selected-background-color` に変更した。
- 固定の黒文字を削除し、本文の文字色を維持する。
- クラスの直接付与は行わず、CSS Custom Highlight API を維持した。JavaScript とプレビュー本文の DOM 操作に変更はない。
- 編集モードの角丸・輪郭線は `::highlight()` の対応プロパティに含まれないため、今回の変更は背景色の共通化とした。

## 検証結果

- `prettier --check lib/preview-finder.js styles/preview-finder.css` が成功した。既存設定の `arrow_parens` について警告があるが、整形違反はない。
- `git diff --check` が成功した。
- Inkdrop 実機でのライト・ダークテーマの表示、次・前の移動、検索解除、ノート切り替えは未確認。

## 実機での確認手順

1. 修正版の CSS を読み込んだ Inkdrop で、同じ検索語を編集モードとプレビューモードで検索する。
2. 通常の一致と選択中の一致の背景色を比較し、ライト・ダークテーマの両方で文字が読めることを確認する。
3. 次・前の移動、検索解除、ノート切り替えを行い、強調表示が正しく更新・解除されることを確認する。

## 動的取得への修正結果

- `getActiveEditor().contentDOM` と編集エリアの祖先構造を複製し、CodeMirror が生成するスコープクラスやユーザー CSS の祖先セレクターを維持した非表示の計測用要素を本文の外へ一時配置する。
- `.cm-searchMatch` と `.cm-searchMatch.cm-searchMatch-selected` の計算済みスタイルを `getComputedStyle()` で取得し、背景色・文字色・下線などの文字装飾・文字の影・対応する WebKit の文字描画プロパティを動的な `::highlight()` ルールへ反映する。
- スタイルシートや編集エリアのクラス・祖先のスタイル変更、OS の配色変更を監視する。検索時と次・前の移動時にも再取得し、CSSOM の直接変更は次の検索・移動時に反映する。
- 自分自身が追加・変更する要素を監視の対象から除き、計算結果が変わらない場合はスタイルを書き直さない。
- 計測用要素は取得直後に削除し、プラグイン無効化時に生成スタイル・監視・予約中の更新処理を破棄する。
- 編集エリアが一時的に存在しない場合は、取得済みの構造を再利用する。まだ編集エリアを一度も取得できていない場合は固定色で代用しない。実機では、プレビューモードでも編集エリアが DOM に保持されることを確認した。
- CSS ファイルから固定のハイライト定義を削除した。角丸・輪郭線は CSS Custom Highlight API の対象外。
