# プレビューのノート切り替えエラー修正計画

## 状態

実装とブラウザーでの回帰検証が完了。Inkdrop の実機操作による最終確認は未実施。

## 目的と原因

ノート切り替え時に発生する `NotFoundError: Failed to execute 'removeChild' on 'Node'` を解消する。

調査資料 `preview-finder.md` によると、`clear()` の `pane.normalize()` が React 管理下のテキストノードを結合・削除し、その後の React の削除処理が失敗する。現在の実装にも該当処理が存在する。

検索処理の `splitText()` と `replaceChild()` もプレビュー本文の DOM を直接変更するため、検索後を含めてノードの同一性と構造を保持する必要がある。

## 修正案

1. Inkdrop の公式 API 資料でプレビュー連携の制約を確認し、実行環境が CSS Custom Highlight API に対応しているか確認する。
2. `lib/preview-finder.js` の検索結果をテキストノードの範囲を表す `Range` として管理する方式へ変更する。CSS Custom Highlight API による描画を第一候補とし、プレビュー本文のテキストノードを分割・置換しない。
3. `clear()` の `normalize()` とマーク要素の置換を廃止し、検索用の描画と保持した範囲だけを解除する。古い DOM 操作用の未使用処理も整理する。
4. 次・前の移動、選択中の強調、表示範囲外へのスクロールを範囲情報に合わせて変更する。公開 `find()` API と既存コマンドを維持する。
5. ノート切り替え、本文変更、プラグイン無効化で検索の描画と参照を解放する。検索 UI 自体の配置も React の更新を妨げないか確認する。
6. `styles/preview-finder.css` に検索範囲と選択中の範囲の描画を定義する。実行環境が対応しない場合は DOM を変更する方式へ戻さず、代替方式を検討して計画へ反映する。

## 対象ファイル

- `lib/preview-finder.js`
- `styles/preview-finder.css`
- 必要に応じて再現手順と修正内容を記すドキュメント

- 検索、検索語変更、空文字による解除、Escape、再検索後にノートを切り替える。
- 複数の一致箇所で次・前の移動と折り返し、スクロールを確認する。
- 本文変更、プレビューモードの切り替え、プラグイン無効化後に強調表示が残らないことを確認する。
- 日本語の IME 入力と Enter 操作、公開 `find()` API を確認する。
- 隣接テキストノードを含む本文について、検索と解除でノードの同一性・構造・本文が変化しないことを検証する。

## 完了条件

プレビュー本文の DOM を変更せず検索と移動が動作し、ノート切り替え時に今回のノード削除エラーを誘発しないこと。検証結果と実機で未確認の項目を報告する。

## 実装結果

- 検索結果を `Range` として保持し、CSS Custom Highlight API で全一致と選択中の一致を描画する方式に変更した。同じテキストノード内の複数一致も検索対象とした。
- `normalize()`、`splitText()`、検索用の `replaceChild()` と未使用の直接 DOM 削除処理を除去した。
- 検索 UI を `document.body` 配下へ移し、本文の React 管理領域へ追加しないようにした。フォーカス中の UI 削除に伴う `blur` の再入による二重削除も防止した。
- 検索位置とストアのノート ID の追跡を分離し、ノートに変更のないストア通知で検索結果が消えないようにした。
- ノートと本文の変更、空文字での検索、プラグイン無効化で検索の描画と参照を解除する。再描画で無効になった検索範囲は次回の移動時に取得し直す。
- API 非対応時は本文の DOM を変更せず、検索ハイライトを行わない。

## 検証結果

- 一時プロファイルの Chrome 155 と、インストール済み Inkdrop に同梱された React / React DOM の本番用モジュールを使用し、31 項目の確認が成功した。テストでは Inkdrop のコマンド登録とストアを模擬した。
- 検索と解除に伴うプレビュー本文への DOM 変更が 0 件であること、隣接テキストノードの参照と本文が維持されることを確認した。
- 検索、ストア上のノート切り替え、React によるテキストノード削除を 20 回繰り返し、例外が発生しないことを確認した。元の実装では隣接テキストノードが削除されることも対照確認した。
- 次・前の折り返し、日本語、絵文字、正規表現の特殊文字、0 件、空文字、本文変更、無関係なストア通知、検索 UI の再表示、IME 入力中の検索抑止、Enter、Escape、再描画後の移動、スクロール、無効化・再有効化、API 非対応時の動作を確認した。
- Prettier の整形確認、`git diff --check`、`npm pack` が成功した。梱包物は一時ディレクトリへ出力した。
- インストール先の旧ファイルを一時ディレクトリへ退避し、修正版の JavaScript と CSS を反映した。リポジトリ内の修正版との一致を確認済み。ノートと設定は変更していない。再読み込みと Inkdrop 実機での最終確認はユーザーによる確認待ち。

## 実機での確認手順

1. 修正版を読み込んだ Inkdrop でプレビューモードを開き、検索せずに複数のノートを往復する。
2. `preview-finder:open` で日本語や英単語を検索し、Enter、次・前の移動、Escape を試す。
3. 検索結果が表示された状態と、解除後の状態でノートを往復し、コンソールに `Failed to render preview` が出ないことを確認する。
4. 本文編集、プレビューモードの切り替え、検索 UI の再表示、プラグインの無効化・再有効化を試し、検索と表示が正常であることを確認する。
